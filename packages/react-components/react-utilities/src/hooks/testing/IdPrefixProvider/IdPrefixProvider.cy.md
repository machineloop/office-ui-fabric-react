# IdPrefixProvider: row135 functional coverage

This utility is `React.Context<string | undefined>.Provider`, declared in
`src\hooks\useId.ts`, not a visual component. It has no DOM wrapper, appearance,
slots, styling, events, focus management or standalone component directory.
It scopes IDs generated by the actual `useId` implementation. Production source,
SSR implementation, public exports, existing tests/snapshots and shared package
configuration are read-only. All authored files are inside this directory.

The existing `useId.test.tsx` has five cases. The existing `SSRContext.test.tsx`
and `SSRContext-node.test.tsx` have two each. The targeted unit command retains
the package's existing Jest preset, SWC transforms and setup and runs those nine
existing cases plus the nine new legacy cases: **18 cases, four suites**, with no
snapshot updates.

The native SSRProvider hydration variant additionally compares complete real
server-rendered markup with and without SSRProvider under the same tree/root
namespace. It explicitly verifies that the wrapper does not change native
React IDs, rather than claiming to exercise the legacy counter branch in Chrome.
Independent legacy SSRProvider counter behavior remains unit-only coverage.

The browser fixture calls the production hook, not a copied ID algorithm or
private helper. It exposes the returned value and uses it in real input labels,
descriptions and expandable-panel controls. The compiler-only negative type
fixtures are not mounted or imported into the browser suite.
The separate `testing\tsconfig.units.json` also type-checks all four targeted
unit sources with Jest types, without leaking Cypress globals into the units.

against their exact scenario identities.

The ID validator rejects duplicates and verifies every label `for` and ARIA
labelledby/describedby/controls token resolves exactly once. Live nodes also
resolve to the same document-level target. The two negative controls are inert,
detached copies; duplicate and unresolved references must throw their precise
assertions. The real audited stage is never made invalid or exempted.

Whitespace is legal in the TypeScript prefix value and returned ID string but
does not imply a usable HTML ID/IDREF. Those boundary cases expose literal
values in data attributes and readable text instead of putting whitespace IDs
on controls. Truthy provided IDs can also collide; callers own their uniqueness.
Likewise, deterministic native SSR renders using the same root namespace may
collide across independently rendered requests. A detached real SSR negative
control characterizes that limit, and two live hydrated roots verify distinct
React `identifierPrefix` values supplied consistently on server and client.
This suite does not claim to load independent copies of React or prove
cross-bundle uniqueness from a single runtime.

## Evidence and parent handoff

Every invocation creates a unique ignored `.evidence` receipt with exact child
commands, exit codes, raw logs, recursive before/after SHA-256 manifests of
**all owned non-evidence files**, and outside source/configuration hashes.
Initial protected bytes are retained in `.evidence\entry.json`; later per-run
outside snapshots also hash existing untracked files. HEAD, branch and outside
status changes are recorded independently, without reverting concurrent work.
Cold prerequisite failures remain failed receipts, not success-shaped fallbacks.
An early sync receipt overlapping our own formatting is intentionally retained
as hash-mismatched development evidence, never final approval evidence.
One later Chrome attempt stalled after successful webpack compilation but
before suite/audit registration. Only that owned process tree was stopped;
its `cypress-r1-interrupted-1791172494767-51924` receipt retains the raw log,
before hashes and an explicit termination record. It claims zero passing
tests, has no completion manifest, and is not approval evidence. The bootstrap
cause is unverified and no infrastructure fix is claimed.

Chrome receipts retain raw JUnit and the corresponding unique browser audit
directory. Validation checks exact unique authored titles/classnames, root and
suite counters, round counts, zero failures/errors/skips/pending/retries, all
final audit identities, full axe results, unique live IDs and CDP events.
JUnit is not replaced by a handcrafted report.

The final verification set uses label `final` for direct rounds 1/2/3, ordinary
round 3, checks, units, isolation, invalid arguments, Nx discovery, preserved
outside bytes, and the explicitly blocked registered/sync probes. `seal` checks
that each selected final receipt's recursive source-before/source-after matches current
bytes, hashes receipts/audits, and records browser-ready status separately from
`coldNxGreen: false`. Its `seal.json` is the parent entry point; raw logs and
full per-case audit identities remain available at their recorded paths.
Older final-labeled receipts are explicitly listed as superseded if their
sources precede a correction; they are not current approval evidence.
